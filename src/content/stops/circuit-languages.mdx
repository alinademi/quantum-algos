<Depth level="kid">

Imagine giving the same recipe to people who speak different languages. One writes the instructions as a list, another uses a programming language, and another has special words for ingredients and actions. The written forms differ, but they can describe the same experiment: prepare two parts, apply a change to the first, connect it to the second, then record both results. The instructions are not the machine itself. Different machines may execute the same recipe or simulate its results. The picture breaks because quantum code has precise conventions about wire ordering and measurement, which can differ between languages even if the mathematical circuit is equivalent.

</Depth>

<Depth level="student">

[Circuit diagrams](/learn/circuits/) can be expressed as code. OpenQASM 3 is a circuit-oriented language with gates and classical instructions. Qiskit and Cirq are Python libraries for constructing and executing circuits; Q# is a quantum programming language. Here each example allocates two qubits, applies H on the first and CNOT from first to second, then measures both. The ideal state before measurement is the Bell state with equal amplitudes for 00 and 11, so either is measured with equal chance. Compare the four snippets and their shared diagram. The simulator implements their common mathematical gates; it does not run or parse those programming languages. Output bit ordering may differ across systems.

</Depth>

<Depth level="engineer">

See the [OpenQASM 3 specification](https://openqasm.com/), [Qiskit circuit guide](https://quantum.cloud.ibm.com/docs/en/guides/construct-circuits), [Cirq circuits](https://quantumai.google/cirq/build/circuits) and [Q# documentation](https://learn.microsoft.com/en-us/azure/quantum/qsharp-overview). The logical state before measurement is $(|00\rangle+|11\rangle)/\sqrt2$. APIs can differ in register ownership, bit display order, and execution semantics; Qiskit commonly displays the highest classical bit first, whereas this lab displays q0 first.

</Depth>
